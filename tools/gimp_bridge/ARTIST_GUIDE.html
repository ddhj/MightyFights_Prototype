Unit Bridge Field Guide

How the game plays a unit's animations, and exactly how to paint them in GIMP so your work drops straight back into the game: repaint what's there, add frames, or draw a whole new unit.

01Quick start

You need GIMP 2.10 or 3.0 (gimp.org). Nothing else: UnitBridge carries everything it needs.

  1. Keep the UnitBridge folder together. UnitBridge.exe reads the game's art from the content\ folder beside it. It writes only into work\ and out\ in the same folder.
  2. Double-click UnitBridge.exe. A window opens with a menu: 
    UNIT BRIDGE -- paint MightyFights units in GIMP
  1  Export a unit to a GIMP file            (writes into work\)
  2  Start a NEW unit                        (writes a blank template into work\)
  3  Check my painted files                  (reads work\, writes out\)
  4  List the units
  q  Quit
  3. Type 1, then the unit's number (for example the Bandit). If GIMP is installed it offers to save a .xcf too; say yes. You get work\Bandit.ora (and work\Bandit.xcf).
  4. Open it in GIMP and paint. Read the file and the rules first: five minutes that save a round trip.
  5. Save with File › Save (.xcf) or File › Export As… (.ora). Keep the file name.
  6. Back in UnitBridge, type 3. It reads everything in work\, tells you what changed row by row, warns about anything the game will get wrong, and writes animated previews you can watch. See checking your work.
  7. Send the painted .ora/.xcf back to the developer. That's the whole loop.

You can also drag .ora/.xcf files onto UnitBridge.exe to check just those.

02How the game animates a unit

Every unit is one picture (a sprite sheet) holding all of its frames, plus a small data file saying which frames belong to which animation, how fast each plays and what happens on special frames. You never touch the data file: the bridge rebuilds both from your GIMP file.

  • Every frame is the same size: the unit's frame size (Peasant 100×64, Bandit 100×70, …). Your art sits somewhere inside that box; the empty space is trimmed away automatically.
  • The unit stands on the bottom of its box. Feet (and shadow) near the bottom edge, like the existing units.
  • Units are drawn facing left. When one turns to face right, the game mirrors the frame. There is no separate right-facing art.
  • The game asks for animations by name: walk when a unit moves, one of five attacks at random when it swings, death when it falls. That's why the rows have fixed names and why every row needs at least one frame.

03The file: rows and frames

You get one GIMP file per unit, laid out as a grid:

  • Every row is one animation. The magenta label says its name, its type and its speed, e.g. walk Move/Walk 130ms.
  • Every column is a frame, left to right. The small number in each cell's bottom-right corner is the frame number.
  • Each cell is the unit's frame size. Image › Configure Grid set to that size, plus View › Show Grid, lines GIMP's grid up with the cells.
  • After each row's last frame come spare empty cells. Paint in them to add frames.
  • The dotted blue line down the middle of every cell is the midline.

Attacks are picked at random. A normal swing is one of low, stab, stick, chop, chopb; a critical is bigchop or lunge and does triple damage. Five genuinely different swings make a unit look alive; five copies of one swing make it look like a machine.

06How the game times them

Each animation has one speed: how many milliseconds each frame stays on screen. 100ms is ten frames a second. The game steps through the row's frames at that speed, then either loops (idle, walk, run…) or plays once (attacks, parry, death).

  • So frame count is duration: a 6-frame attack at 100ms takes 0.6 seconds; add two frames and it takes 0.8. Units fight at the speed of their animations.
  • The speed itself isn't in the GIMP file. If a row feels too fast or slow after you've drawn it, tell the developer the new speed — it's a one-number change.
  • Watch the previews (menu 3): they play at the game's real speed.

07Adding and removing frames

A row's frames run from its first cell to its last cell with anything in it.

  • To add a frame, paint into the first spare cell after the row's last frame. Need more room than the spares? Tell the developer, or export again with more spares.
  • To remove frames, erase the row's last cells completely (every pixel, shadow included).
  • A gap in the middle — an empty cell with frames after it — stays as a blank frame (the unit vanishes for one frame). That's almost never what you want.
  • A few units (Drau) end some animations on blank frames on purpose; those are kept as long as you leave them blank.

08Face left, stay on the midline

This is the one rule that breaks the game when it's missed. When a unit turns around, the game mirrors the frame across its middle. A body standing on the middle stays put; a body standing off to one side jumps to the other side — and the unit's position in the fight jumps with it, which can make it twitch back and forth while it walks.

  • Keep the body (not the weapon) centred on the dotted blue line, especially in walk, run and flee.
  • Lunges and steps inside an attack are fine: it's where the body stands on average that matters.
  • The check (menu 3) measures this on the movement rows and warns if it's off.

09Hit frames

An attack only does damage on one frame: the moment the weapon connects. That frame is marked with a red dot on the #hit frames layer.

  • One dot per attack row, in the cell of the frame where the blow lands. Where in the cell doesn't matter.
  • Move the hit by erasing the dot and painting one in another cell of the same row.
  • An attack row with no dot never deals damage. The check warns about every one. (Right now most units have none — placing them is some of the most useful work you can do.)
  • If you add or remove frames, check the dot is still on the right one.

10Starting a new unit

Menu 2 makes a blank template for a brand-new unit. It asks for:

  1. A name — letters and digits, e.g. Goblin.
  2. A unit to copy — the new one gets its rows and speeds (Enter picks the Peasant). Its frames appear faintly behind on the #reference layer, so you can match size, baseline and the swing's timing.
  3. A frame size — Enter keeps that unit's size; a bigger unit can ask for more, e.g. 140x96.

Every row needs at least one frame before the check will accept it. You can start rough: one frame per row gets a unit into the game; fill in the rest later.

12Rules for the file

Don'tWhy
resize or crop the canvasthe cells stop lining up with frames (the check refuses it)
move rows up or down, or reorder thema row's position is its name: walk frames would become run frames
delete or rename the #guides layerit tells the bridge which unit the file is (without it, the file name must be the unit's name)
leave a row completely emptythe game asks for every row by name
use blend modes other than Normalonly plain layers merge correctly (opacity is fine)
draw facing rightthe game mirrors the art to face right itself

Layers whose names start with # never go into the game, so a #notes layer for the developer is welcome.

13Checking your work

Menu 3 reads every file in work\ and reports, per unit:

Bandit: changed (80 frames)
  walk       5 -> 6 frames; repainted 05
  chop       hit none -> 02
warning: Bandit.ora: attack 'low' has no hit frame -- it will never deal damage
  • Previews: one looping GIF per animation in out\_preview\<Unit>\, three times size, at the game's speed. The hit frame shows a small red square. Open them in any browser or image viewer.
  • The rebuilt sheet goes in out\. That's the file the game would load — only for your curiosity; you don't need to send it.
  • warning means "the game will take this, but check it". ERROR means nothing was written: fix what it says (usually a resized canvas or an empty row) and run it again.

14Sending it back

  • Send the .ora / .xcf files you painted, from work\. They are the source of your edit; the developer imports them.
  • Using GIMP 3? Send a .ora too (File › Export As…) — GIMP 2.10 may not open a GIMP 3 .xcf.
  • A #notes layer is a good place for anything you want the developer to know: "speed this up", "chopb isn't finished".

15Glossary

sheet
the one picture holding all of a unit's frames, packed tightly
frame size
the box every frame of a unit is drawn in (one cell of the grid)
row / animation
one named animation: walk, chop, death…
speed
milliseconds each frame stays on screen
hit frame
the one frame of an attack where damage happens (a red dot)
midline
the dotted blue line the game mirrors each frame across when the unit turns
spare cells
empty cells after a row's last frame; painting there adds frames
.ora
OpenRaster, a layered image format GIMP opens and saves; needs nothing extra to check
.xcf
GIMP's own format; checking one needs GIMP installed
